# Coordination benchmark baseline — v0.8.0 release validation

## Release gate summary (2026-10-13)

All live correctness gates passed on disposable Cloudflare infrastructure. The six-scenario matrix, one 24-participant owner-contention run, the six-participant 500 ms cadence control and five cold restarts recorded 6,825 operations with zero unexpected errors, and all 24 invariants passed. A separate three-test persistence gate confirmed task data survived acknowledged DO eviction and restart.

The isolated Worker used its own D1 database, DO namespace and R2 bucket. All global D1 migrations applied before deployment, including 0033 and 0034; shared DO migrations 41 and 42 applied on first request. Worker and benchmark source was `ab6f6f45`, with public release metadata at 0.8.0, and `/api/health` reported that version and commit. The client was macOS arm64 in Wrocław. The existing service was not modified. Cleanup destroyed the project with all stores verified empty, then removed the disposable Worker, D1 database and R2 bucket; Cloudflare reads and account-wide listings confirmed removal.

Latency remains advisory. Every compared signal was faster than the 0.7.0 baseline: eight-participant contended acquire p95 went from 390 to 359 ms, fenced update from 444 to 350 ms, signal send from 442 to 426 ms, journal replay from 468 to 372 ms, owner-contention acquire from 921 to 872 ms, and cold-first-read p50 from 246 to 173 ms. Plain `GET /api/health` round trips were 57 ms, the same as during the 0.7.0 run, so no A/B comparison against the previous release was needed.

The 500 ms cadence control missed none of its 360 deadlines (the advisory target is 0; 0.7.0 missed 2). Its acquire p95 was 263 ms.
